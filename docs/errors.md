# Ошибки

Ядро возвращает два вида отказов, не путай их:

- **`Deny` без ошибки** — «доступа нет по политике». Нормальный ответ: пользователь не имеет права, роли нет, данных нет.
- **Ошибка** — «проверка не удалась по техническим причинам». Не штатная ситуация: упал резолвер, запрошено нулевое право, политика собрана неверно.

Принцип простой: техническая причина — ошибка, политическая — `Deny`.

## Sentinel-значения и `errors.Is`

Все ошибки ядра — sentinel-значения, обёрнутые `%w`. Сверять их нужно только через `errors.Is`, не через `==` — ошибка может прийти в обёртке.

```go
var (
	ErrEmptyChain       // ось ScopeChain пуста — нет ни одного звена
	ErrInvalidChainRule // правило комбинации не Nearest и не Union
	ErrNoMatrixForKind  // в Matrices нет матрицы для Kind из Type
	ErrNilResolver      // резолвер равен nil
	ErrNilMapScopes     // экстрактор MapScopes равен nil
	ErrZeroPerm         // запрошенное право равно нулю
)
```

```go
decision, err := checker.Check(ctx, user, doc, 0)
if errors.Is(err, rolego.ErrZeroPerm) {
	// нулевое право — ошибка программиста в месте вызова
}
```

## Таблица «ситуация → что возвращается»

| Ситуация | Что возвращается |
|---|---|
| запрошено право `perm == 0` | `(Deny, rolego.ErrZeroPerm)` |
| у ресурса нет звеньев | `(Deny, nil)` |
| все маски ролей пусты по правилу оси | `(Deny, nil)` |
| упал резолвер | `(Deny, err)` — ошибка резолвера |
| право не выписано в матрице | `(Deny, nil)` |

Две строчки с `nil` — это не ошибки, а политика «нет данных — доступа нет». Ошибка резолвера — единственный случай, когда возвращается чужая ошибка: ее оборачивает ядро и отдаёт наверх без потери.

## Ошибки из резолвера

Резолвер может вернуть свою ошибку (недоступна БД, сбой типизации). Ядро не прячет и не заменяет её: `Check` возвращает `(Deny, err)` с оригинальной ошибкой внутри, и ты сверяешь её своим `errors.Is`:

```go
if errors.Is(err, sql.ErrNoRows) {
	// резолвер сказал, что записей нет
}
```

## Составные ошибки `Validate`

`Validate()` при старте собирает все противоречия сразу одной ошибкой через `errors.Join`. Каждый компонент — своя sentinel, поэтому `errors.Is` на суммарной ошибке работает:

```go
err := checker.Validate()
if errors.Is(err, rolego.ErrEmptyChain) && errors.Is(err, rolego.ErrNoMatrixForKind) {
	// найдено сразу два противоречия
}
```

Список проверок `Validate`:

| Проверка | Sentinel при провале |
|---|---|
| есть матрица для `Kind` из `Type` | `ErrNoMatrixForKind` |
| ось не пуста | `ErrEmptyChain` |
| правило комбинации корректно | `ErrInvalidChainRule` |
| резолвер не nil | `ErrNilResolver` |
| экстрактор не nil | `ErrNilMapScopes` |
