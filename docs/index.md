# rolego

**Актуальная версия:** {{ config.extra.version }}

**Ролевая авторизация на битовых масках для Go.**

Библиотека отвечает на один вопрос: «может ли субъект S сделать действие `Perm` над ресурсом R?». Например: «может ли Алиса записать в документ 42?»

Роли и права — это не строки и не таблицы в базе, а константы твоего пакета (`1 << iota`). rolego ничего не хранит: где у субъекта какая роль — вычисляет твой код из твоих данных (карты членства, правило владельца, запрос к БД, LDAP). Библиотека только собирает всё это в решение `Allow`/`Deny`.

## Модель: шесть сущностей

Прежде чем писать код, держи в голове картинку. Все термины ниже отвечают на свой вопрос, и этот вопрос же они слышат на входе.

| Сущность | Тип | Кто объявляет | Вопрос |
|---|---|---|---|
| Роль | `Role` | ты, константа `1 << iota` | «кто ты?» — зритель, редактор, менеджер |
| Право | `Perm` | ты, константа `1 << iota` | «что тебе можно делать?» — читать, изменять |
| Тип ресурса | `Kind` | ты, метка-число | «что это за звено?» — документ или проект |
| Звено | `Scope` | твой экстрактор `MapScopes` | «где именно?» — документ №42, проект №7 |
| Ось | `ScopeChain` | ты при сборке `New` | «как объединить роли с разных звеньев?» |
| Матрица | `Matrices` | ты при сборке `New` | «что разрешено роли на этом типе ресурса?» |

Роль «кто ты», право «что можно» — их можно переиспользовать между разными ресурсами. Тип и звено привязаны к конкретному предмету: у «документа №42» тип «документ», у «проекта №7» тип «проект».

**Звено (`Scope`) — просто «адрес» места в иерархии: тип + номер** («документ №42»). Ресурс может занимать несколько адресов: документ №42 лежит в проекте №7 — у него два адреса. Твоя функция-«адресная книга» (`MapScopes`) объявляет, какие адреса у ресурса.

Поверх шести сущностей есть две **опциональные надстройки**, которые модель не трогают: `WithHierarchy` — старшинство ролей (права предков транзитивно добавляются в матрицы при сборке) и `Registry` — строки из унаследованной БД ↔ биты (живёт на границе твоего кода).

## Кто за что отвечает

Половину работы делаешь ты, половину — библиотека. Граница принципиальная: **где роли** — твои данные, **как из них решить** — код rolego.

| Твой код | Библиотека |
|---|---|
| роли и права — константы | обойти звенья ресурса от самого глубокого к корню |
| типы ресурсов `Kind` — метки | для каждого звена спросить `Resolver.RolesAt` |
| экстрактор `MapScopes` — «как из ресурса достать звенья» | объединить маски ролей по правилу оси |
| резолвер `Resolver` — «где лежат роли и персональные права субъекта» | сверить итог с матрицей (и грантами), вернуть `Allow`/`Deny` |
| матрица прав — «что может роль на типе» | ошибку резолвера пробросить как `(Deny, err)` |

## Флоу одной проверки

Вопрос задаётся так: `checker.Check(ctx, subj, res, perm)`. Внутри проходит конвейер:

```
MapScopes(res) → звенья [проект, документ]
  → на каждом звене Resolver.RolesAt(res) → роли и персональные права субъекта
  → объединение ролей по правилу оси (Nearest / Union); гранты — OR по всем звеньям
  → (права ролей | гранты) ∩ perm != 0 → Allow / Deny
```

Склеив однажды `MapScopes`, `Resolver`, матрицу и ось в `Checker`, ты потом только задаёшь вопросы. Как именно всё склеивается — пошагово в [Быстром старте](quickstart.md).
